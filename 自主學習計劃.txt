個人化智慧 TDEE 計算器與健康數據分析系統開發計畫分為四大階段：
第一階段：需求定義與基礎建置 (第 1-4 週)
這個階段重點在於「統一標準」，避免後續寫程式時邏輯打架。
* 醫學與營養參數確立： 兩人分頭查找資料，一人負責確認 Mifflin-St Jeor 基礎代謝公式與活動量乘數；另一人整理減脂、增肌的巨量營養素（碳水、蛋白質、脂肪）黃金比例，並統整成一份共用數據表。
* 系統架構視覺化： 共同使用 draw.io 或 Figma 繪製流程圖，明確定義哪些步驟需要防呆（例如體重不可輸入負數），並劃分前端（介面）與後端（計算）的界線。
* 開發環境初始化： 推派一人創立共用的 GitHub 數據庫（Repository），雙方皆需在自己的電腦上完成 Python 環境建置，並成功執行第一次的 git clone 與 commit。
第二階段：核心開發與版本控制 (第 5-9 週)
進入實作期，建議採「功能分工」，並在第 9 週進行關鍵整合。
* 後端邏輯開發： 同學 A 負責撰寫終端機（CLI）的數值輸入與例外防呆攔截；同學 B 負責撰寫 TDEE 核心計算式，與目標熱量的判定模組。
* 前端框架導入： 雙方共同閱讀 Streamlit 的官方文件，將前面寫好的純文字計算邏輯，套用上網頁版的輸入框（st.number_input）與按鈕。
* 代碼合併實戰： 這是最重要的第 9 週。雙方將各自的功能在 GitHub 上提交 Pull Request（PR），練習解開代碼衝突（Merge Conflict），確保 v1.0 網頁能順利在兩人的電腦上運行。
第三階段：視覺進階與數據導入 (第 10-13 週)
系統成型後，透過真實數據讓專案具備醫學資訊的亮點。
* 圖表與線上部署： 利用 matplotlib 繪製營養素圓餅圖並整合至網頁。完成後，撰寫清楚的 README，並將系統一鍵部署至免費的 Streamlit Community Cloud。
* 雙人交叉對照： 互相輸入家人的生理數值，並與網路上知名的 TDEE 計算機進行比對，記錄下兩者的數值落差與可能原因。
* 動態數據整合： 匯出一段真實的穿戴裝置 CSV 紀錄（例如早晨打羽球時的心率或消耗卡路里），利用 Pandas 套件讀取該檔案，讓系統能自動判定活動量，取代手動輸入。
第四階段：技術報告與成果收斂 (第 14-18 週)
將系統開發的歷程，轉化為醫學與資工教授都看得懂的專業文獻。
* 報告架構分工： 建立 HackMD 共筆。同學 A 主筆「專案動機」與「醫學理論基礎」；同學 B 負責繪製並解析「系統架構圖」與「GitHub 代碼分工圖」。
* 數據洞察撰寫： 共同將第 13 週的 Pandas 數據分析結果，以及第 12 週的對照誤差，以圖表形式寫入測試報告中，證明系統的實用性。
* 反思與最終輸出： 寫下跨部門協作（如解決 Git 衝突）的溝通成本與心得，並提出未來可串接 API 的展望。最後進行全篇排版，導出最終 PDF 檔案。
